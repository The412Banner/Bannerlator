# Bannerlator 2.8.1 — Detailed Changelog

**The full, in-depth breakdown of everything added and changed since 2.8.** The release page has the short version; this is the "understand exactly what changed and why" version. 2.8.1 is a **catch-up stable** — it ships all the work that piled up on `main` while the Virtual Controller Pro update (PR [#156](https://github.com/The412Banner/Bannerlator/pull/156)) finished its final fixes. That work lands in **2.9**, coming in the next few days.

> ⚠️ **Testing a 2.9 pre-release?** 2.8.1 does **not** include Virtual Controller Pro (PR #156). Updating removes those controller setups. If you want to keep them, stay on your pre-release and wait for 2.9.

## 🎛️ In-game HUD & overlays

### The Fusion HUD — a fourth in-game performance overlay
Bannerlator already had three HUD styles (Classic, GameHub-style, GameNative-style). **Fusion** is a new fourth style with a clean, MangoHud-inspired look — built *our* lightweight way.

- **It is a composited Android overlay, not the real MangoHud Vulkan layer.** It draws on top of the game surface using plain Android `Canvas` and refreshes about once a second **off** the render/present path, so it costs almost nothing during gameplay — and it works on *any* renderer (Vulkan, OpenGL, wrapper/Zink) without hooking the driver.
- **Five tap-cyclable sizes** — tap the HUD to cycle:
  - **Full** — the everything view (per-metric rows).
  - **Tiles** — a 2-column grid of metric tiles.
  - **Pill** — an FPS-forward capsule: the API on top, big FPS in the middle, clock below.
  - **Minimal** — big FPS + the percentile lows + a frametime graph.
  - **Mega** — a richer, second "full" view with **per-core CPU** (C0…Cn %, MHz) plus full system info (swap, net, resolution, Proton/Wine, the graphics wrapper, DXVK version, session time).
- **Per-metric toggle chips** — every value can be turned on/off, and each size only offers the chips it actually renders (so the settings aren't one giant undifferentiated list).
- **Percentile lows** — 1% / 0.1% / 0.01% lows computed from a per-present frametime ring buffer, plus an optional FPS decimal.
- **A subtle clock** in every size.
- **Lock-in-place** — long-press any of the four HUDs to lock it; tap/drag freeze while locked, with a fading padlock badge. Shared across all four styles so they can't drift apart.

The metric backend (`FpsCounter` for present-tick counting + frametime percentiles, `HudMetrics` for the cached sysfs/procfs snapshot) is shared with the other three HUDs.

> 🧩 **The Fusion HUD is also open-sourced as a standalone, drop-in library:** [github.com/The412Banner/FusionHUD](https://github.com/The412Banner/FusionHUD). Any Winlator / Wine-on-Android fork can add it without re-implementing the metric plumbing (GPL-3.0 with an attribution requirement). See its [technical write-up](https://github.com/The412Banner/FusionHUD/blob/main/docs/FUSION_HUD.md) for how every metric is read.

### Real graphics-API detection
Previously the HUD's engine label was derived only from the container's DX wrapper, so it could **mislabel** a game — e.g. showing "DXVK" for a game that actually drives Vulkan directly.

Now the HUD shows what the game is *actually* running. It scans the running process's loaded PE DLLs and resolves **D3D first** (a DXVK/VKD3D game also loads `vulkan-1.dll`, so D3D must win):
- `d3d12.dll` / `d3d12core.dll` → **`D3D12 · VKD3D`**
- `d3d11` / `d3d10` / `d3d9.dll` → **`D3D11 · DXVK`** (or the configured wrapper — VEGAS / WineD3D)
- if **no** D3D DLL is present: `winevulkan.dll` / `vulkan-1.dll` → native **`Vulkan`**; `opengl32.dll` → **`Zink`** (when guest GL is routed through Zink) or **`OpenGL`**

So an idTech title like Doom Eternal now reads **`Vulkan`** instead of a wrong "DXVK", and the D3D feature-level version is shown alongside the translator.

### Cross-vendor metrics
The HUD's GPU load, GPU clock, CPU/GPU temperatures and VRAM readers were broadened well past Adreno. They now probe vendor-specific sysfs across **Adreno (KGSL) · Mali (`gpuinfo` / Exynos `gpusysfs`) · PowerVR · amdgpu / Xclipse `sgpu` · panfrost · Qualcomm `cpuss` · MediaTek `mtktscpu`/`mtktsgpu` · Exynos**, plus a `/sys/devices/platform` scan for hashed vendor nodes and a wider devfreq walk. A metric a device genuinely doesn't expose shows "—" rather than a fake `0`, and the Adreno path stays first so nothing regresses there.

*Known gap:* a truly vendor-agnostic VRAM figure needs `VK_EXT_memory_budget`, which requires an NDK rebuild — it's documented as a `TODO(native)`. On Adreno, VRAM currently shows a miss because KGSL exposes no per-process memory node in sysfs.

### Export HUD diagnostics
A one-tap **"Export HUD diagnostics"** button (in the in-game HUD drawer and the FPS-counter settings dialog) writes a plain-text sensor report to your Downloads. For each metric it lists the **resolved source path**, or on a miss the exact candidate paths it tried plus an "exists on this device" dump (thermal zones, devfreq nodes, kgsl/mali/drm). It **saves silently** (no share sheet, no interruption). Send that file in and support for a whole device family can be added from one path.

### HUD polish
- Temperature **danger colours** driven by the device's own thermal trip points, with a **°C / °F** toggle.
- The shared lock-in-place behaviour described above.

## 🌐 Community Configs

### Matching a config to the right game — by Steam appId
Two fixes here, one client-side and one server-side.

- **The wrong-game-name fix (#[167](https://github.com/The412Banner/Bannerlator/issues/167)).** `GameMatcher` used to break ties by config-count popularity, which could surface a more-popular game over yours on an ambiguous name (e.g. Veilguard over Inquisition). It now tie-breaks **deterministically** and, on a genuine tie, shows a **"Which game is this?"** picker — remembered per shortcut so you only answer once. It also strips a `"tm"` noise token.
- **Match by appId first.** When a shortcut carries a Steam appId (Steam-identified games persist one, and it rides the `.desktop` through renames), the importer now resolves the game by that **exact appId** against the appid-keyed canonical index *before* falling back to fuzzy name matching — and skips the picker entirely on a hit. A renamed or exe-abbreviated shortcut stops matching the wrong game.
- **The export + server side.** Exported configs now stamp the game's authoritative appid into `meta.steam_appid`, and the canonical-index builder (`bannerlator-game-configs`) aggregates uploads **by that appid** — so a config for the same game merges under the same canonical entry regardless of how the folder was named.

### A shared config now saves and restores your *whole* setup
An audit found the exporter was silently **dropping** a cluster of settings added since the community-config system was built — they never travelled, so importing a config couldn't restore them. Now carried and re-applied:

- **The entire HUD configuration** (`fpsCounterConfig`) — all four styles including Fusion, size, every chip, colours, lock. This one was container-only at launch, so a per-shortcut override was wired in so an imported HUD theme actually applies (with symmetric write-back, and the master HUD on/off gate left untouched — a config *themes* the HUD; the recipient still chooses whether the HUD is shown).
- **Motion-aim** (all gyro keys), **in-game refresh cap**, **custom startup services**, **frame-gen model**, **upscaler (`scalingMode`)**, and **dual-motor vibration**.

Export and import were kept **symmetric** — nothing is exported without a working apply path. Two settings were deliberately **not** carried because they describe your hardware, not the game (gyro deadzone/smoothing), or belong to a WIP feature (frame-gen tuning params). This grew the settings a shared config carries from **34 to 50** (+16, ~+47%).

This round-trip was **device-verified**: all 50 settings were set on a shortcut, exported, the shortcut deleted and re-added fresh, then the config imported — **49/50 came back byte-identical** (the one difference, `wincomponents`, is the app canonicalizing a partial value at export time and round-tripping it faithfully).

### Big Picture — full Community Configs
Community Configs is now a first-class Big Picture experience with complete controller / D-pad navigation (per-game config sheet, every menu navigable).

## 🎨 Graphics, drivers & frame generation

### Driver-source management (#[160](https://github.com/The412Banner/Bannerlator/issues/160))
Add / remove / toggle your own adrenotools driver **feeds**, with a multi-feed model. The built-in **MTR / WinNative Drivers** list combines MTR with WinNative-Emu driver releases and auto-updates.

### In-game refresh-rate unlock
In-game refresh dropdowns were previously locked to 60 Hz because the pure-Java X server had no RandR extension, so Wine fell back to a single hardcoded 60 Hz mode. A from-scratch `RandrExtension` was added (advertising RandR 1.1 deliberately) plus rates from the device's supported modes — so you can pick **90 / 120 / 144 Hz** from the drawer where the panel and layer support it, with a container default + per-game override and a max-rate ceiling. Requires the refreshed Proton 11.0-1 / 10.0-4 layers; older layers keep it off by design.

### Frame generation
- **bionic-fg shader pool** — models 2 and 3 added, with live model chips.
- A **Xiaomi / HyperOS** frame-gen fix (parked the `libjpeg.so` shadow).
- **bionic-fg is temporarily non-selectable** after repeated false-positive "it's working" reports on what is still an experimental, WIP feature. **Use lsfg-vk** for frame generation for now; bionic-fg returns as selectable once it's proven to work correctly and as intended.

## 🚀 Startup, import & files

### Custom per-service startup (#[168](https://github.com/The412Banner/Bannerlator/issues/168))
A fourth **Custom** startup mode alongside the existing presets, letting you pick exactly which services launch (winebus / winehid / …) via per-service toggles. It's set per container (the default for new shortcuts) and overridable per game, which then becomes the source of truth at launch. Defaults to all-off.

### Smart Game Import
Adding a game is smarter: it auto-names the shortcut, identifies the game (Steam `steam_appid.txt` / footprint), pulls cover art (SteamGridDB by appId → by name), recommends missing components, and gives you an editable **Game Details** page (name, cover, genres, description). The `+` button, bulk folder import, and File Manager "Add to Shortcuts" all run the same identifier so they behave identically.

### Drive letters + games-folder bulk import
- Drive letters are assigned **per storage volume** rather than per game, so SD-card games stop exhausting/clashing letters.
- **Add a whole games folder at once** — a scanner ranks each sub-folder's executables (picking the real game exe over launchers), confirms genuinely ambiguous cases, and imports the lot.

### File Manager overhaul
Multi-select + bulk operations, **instant same-volume moves** (`renameTo` fast-path instead of rewriting every byte), merge-on-conflict paste, **archive extraction** (zip / 7z / tar, with Zip-Slip guarding), search / sort / hidden-files / free-space, and grid + compact views.
