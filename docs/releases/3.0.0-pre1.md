# Bannerlator 3.0.0 Pre-Release 1 — Detailed Changelog

**The full, in-depth breakdown of everything added and changed on `main` since 2.9.9.** The release page has the short version; this is the "understand exactly what changed and why" version.

**This is a pre-release (opt-in beta), not a stable cut.** It is only offered to users who have turned on **Settings → Include pre-releases** in the in-app updater. Everyone on the default (stable) channel stays on 2.9.9 and is never auto-offered this build. It installs **entirely app-side** — **no ImageFS reinstall** — so your containers, themes, custom accent and per-game settings carry over untouched.

> 3.0's headline is a **ground-up audio stack** — the "coming in 3.0" audio teased in 2.9.9 — landing here for the first time alongside a clean-room frame-generation replacement, a new Contents hub, and the Adreno a6xx driver-crash fix.
>
> **Why this pre-release exists:** to get the new **DirectAudio** engine and the **adaptive PulseAudio / ALSA** stacks into testers' hands early. It deliberately does **not** yet include the reworked controller-input / player-slot system — see [What this build does *not* include](#-what-this-build-does-not-include-yet) below.

## 🔊 A ground-up audio stack (3.0's headline)

2.9.9 promised a "ground-up audio stack" for 3.0. This is it. Three engines, all made adaptive, all controllable live, with a strict configuration model so settings never leak across engines or scopes.

### Adaptive PulseAudio 13 sink
The PulseAudio path (the default engine) was rebuilt from stock PulseAudio 13 in CI with a re-derived AAudio sink module:

- **Adaptive buffering** — the sink grows its buffer on underrun (xrun) instead of crackling, then holds the smaller latency when the stream is stable.
- **Route-change recreate, foreground *and* background** — plug/unplug wired, USB-C, Bluetooth or HDMI and the sink is recreated cleanly onto the new device; route changes made while the app is backgrounded are recovered on return to foreground.
- **Background/foreground smoothing** — the sink only recreates on a *real* route change, not on every focus flip, so pausing and resuming no longer pops the audio.
- **Mute-bug fix** — the module is now handed `volume=1.0` so an absent-volume default can't leave the sink silent.

### Adaptive ALSA driver
The ALSA engine got the same adaptive treatment:

- **Grow-on-underrun + reopen-on-route-change**, mirroring the PulseAudio behaviour.
- **`PERFORMANCE_MODE_NONE` fix** — the ALSA path no longer requests a performance mode it never actually read, and its buffer bookkeeping is now honest.
- **Full settings mirror** — the ALSA engine exposes the same presets and fine-tune rows as the others.

### DirectAudio — a new third audio engine (experimental, opt-in)
A brand-new first-class audio engine sits alongside PulseAudio and ALSA. Under the hood it's a **native Wine → Android AAudio driver** (`winedirectaudio.drv`) that hands the game's audio **straight to Android's low-level AAudio API — with no PulseAudio or ALSA middleman** in between. That shorter path is the whole point: fewer hops is headroom for **lower latency and cleaner output**. It's a young, purpose-built, open project with real room to grow — the long-term aim is for DirectAudio to become the **lowest-latency, best-sounding of the three engines**, surpassing the PulseAudio and ALSA paths as it matures. It's **experimental today**, which is exactly why it's landing in a pre-release first — so testers can shape it.

> 📦 **Open source (LGPL-2.1):** [github.com/The412Banner/directaudio](https://github.com/The412Banner/directaudio) — the standalone driver, consumed here as a submodule. Read the source, follow its progress, or contribute.

The engine itself:

- **Opt-in and clearly labelled experimental** — the default stays PulseAudio; DirectAudio is a choice, with a warning on the selector.
- **Bundles driver v1.3.1**, overlaid into the Proton layer at launch.
- **⚠️ DirectAudio only works with the four rebuilt arm64ec compatibility layers** — **Proton 10.0-4, 11.0-1, 11.0-3, and 11.0-5** (arm64ec). Its `winedirectaudio.drv` is an arm64ec PE built against exactly those builds; on any other layer selecting DirectAudio does nothing (the selector greys it out and the launch path falls back to the default driver). You download these layers **in-app through Contents** (they're published in the `contents.json` catalog). The bundled driver **auto-updates** into whichever of these you're on (the Wine-10 `10.0-4` build and any of the Wine-11 `11.0-x` builds each get their ABI-matched driver set).
- **Live in-game control** — the in-game audio cog applies DirectAudio changes through the driver mailbox without a relaunch.
- **Sensible presets** — real preset buffers, the 33 ms default the driver already ships, a safety-net Low preset on every engine, and `POWER_SAVING` is deliberately *not* offered for DirectAudio because it churns under FEX.

### Audio controls, everywhere (the cog)
Audio is now tunable from every scope that matters, with the same UI:

- **Container editor cog** and a **per-game shortcut cog** (Compose `ShortcutSettingsDialogScreen`), plus a dedicated **in-game Audio tab**.
- **Presets + fine-tune rows** with **per-preset and per-row "?" help**, and greyed rows now *show* what the selected preset actually applies rather than looking broken.
- The cog's **latency slider actually sets the buffer** now (it was previously inert for DirectAudio).
- The in-game cog **no longer deletes hand-set driver knobs**, and the DirectAudio knobs are available in the add-variable catalog.

### Strict per-scope / per-engine configuration (no bleed)
Under the hood the audio settings were re-architected so configuration can't leak across axes:

- **Independent per-engine preference stores** — PulseAudio, ALSA and DirectAudio each keep their own settings; switching engines no longer inherits stale values from another.
- **Per-scope hierarchy** — persistent (per-container, engine-scoped env keys), runtime (ephemeral `banner_audio_<engine>`), and in-game (shortcut-only) are kept separate with a full baseline seed at launch, so nothing bleeds between container / shortcut / in-game.
- **Malformed env variables** are skipped (with an explanation while you type) instead of crashing the launch.

## 🎞️ Frame generation: bionic-fg → clean-room win-fg

The previous frame-generation layer (bionic-fg) was **removed** because its LSFG weights were proprietary. It is replaced by **win-fg**, a clean-room implementation built to honour that takedown:

- **All tainted models are gone** from the app, READMEs and license/third-party notices; win-fg and its FidelityFX FSR3 (MIT) optical-flow front-end are recorded instead.
- **New in-game controls** — frame generation is now **Off / On (On = 2×)**; turning it On reveals the model choice (**Optical flow / Bidirectional**) and a flow-scale control. The old bionic-fg model toggles, spec cards, launch splash and in-game drawer badge are all replaced with win-fg's.
- **Device-proven runtime .so bundled** (present-fix + hot-reload + always-init).

> ⚠️ **Known limitation this build:** win-fg is still in on-device **bring-up**. Its frame-*insertion* stage (Phase 3) isn't finished, so **frame generation currently runs as passthrough** — the pipeline is wired end-to-end and the UI is live, but generated frames aren't inserted yet. This is exactly why 3.0.0-pre1 is a pre-release. If you want working frame generation today, **lsfg-vk** remains available and unaffected.

## 📦 The new Contents hub

A new **Contents** manager replaces the scattered add/install entry points with one multi-source hub for drivers, components, wrappers and raw archives:

- **Hub screen with tabs and master-detail** — badges, a "My Files" area, and an **Installed** tab to view and remove drivers and components you've added.
- **Multi-source remote engine** — a type registry and raw-archive library pulling from multiple sources, with **token-based cross-source search** and a clear-search button.
- **Community repos are opt-in**, per-source toggles with grouped provenance so you see where each item comes from; the old default source was dropped.
- **In-app file picker** on the install buttons, and search results shown in the right pane in landscape.
- **Process-lifetime installer** — the `.wcp` pipeline, adrenotools drivers and a keep-raw option run for the life of the install.
- **Layout & polish** — a left `NavigationRail` for tabs in landscape / top `TabRow` in portrait, `VerticalDivider` fix for the empty detail pane, scroll-clipping fixes at large UI scale, de-duplicated titles/keys (fixing a duplicate-key crash) and ghost white-button fixes.
- Adrenotools is **hidden from the drawer** and folded into the Contents entry in its System slot.

## 🖥️ Turnip / driver-select stability (the Adreno a6xx crash fix)

A hard crash when selecting custom adrenotools drivers on **Adreno a6xx** devices is fixed:

- **Proprietary Qualcomm driver blobs are no longer probed in-app** — probing them in-process could smash the stack (`SIGABRT`) or corrupt the linker heap. Custom drivers still load and work at game launch; they simply show a **reassuring note** in the picker instead of being probed.
- **Turnip / Mesa drivers still list their extensions** as before; only the proprietary blobs are skipped.
- **The probe was moved off the main thread** (killing an ANR), serialised behind a mutex, with a **`SIGABRT` guard** as a backstop.
- A true **0 / 0** result now shows the reassuring in-game note, never a misleading "0 extensions" error.

## 🩹 X-server correctness & leak fixes

Several portable correctness fixes in the pure-Java X server:

- **DRI3 pixmaps are now registered as client resources**, stopping a resource leak.
- **`GetAtomName`** malformed-reply and out-of-range-atom crash fixed.
- **`KeyValueSet`** iterator no longer drops single-item configs.
- **Long-exe-name games** are now correctly suspended on pause (matching the full cmdline, not the truncated `comm`).

> A separate Present/Sync per-window resource-prune leak fix was trialled and **reverted** — on-device it forced a CPU pacer that tanked framerates — so it is intentionally **not** in this build. There is no framerate regression here.

## ✨ Appearance & HUD

- **Interface Scale** — new UI + font-size sliders (with −/+ steppers) in Appearance, defaulting to **90%**. Verified not to affect the on-screen controls, HUD, or the game surface itself.
- **HUD battery temperature** — the Fusion HUD pill now shows a **"BAT °C"** chip next to the RAM chip.

## 🔧 Updater, diagnostics & misc

- **Update-cache pruning** — the in-app updater now prunes stale downloaded APKs before each download *and* on cold start, fixing an accumulation that could reach ~10 GB over many versions.
- **No-root native-crash capture** — native crashes are captured via `ApplicationExitInfo` even without root, and the crash tombstone proto is decoded into a real backtrace for bug reports.

## 🚫 What this build does *not* include (yet)

To be explicit, because it's a common question:

- **The reworked controller-input / player-slot system is NOT in this build.** Controller behaviour here is **exactly the same as 2.9.9** — the same hot-plug, slot and on-screen-controls handling. The newer controller work (slot-takeover / player-assignment overhaul) is still being finished and verified and has not been merged; it will come in a later 3.0 build. Updating to 3.0.0-pre1 does **not** change how your controllers behave versus 2.9.9.

This pre-release is intentionally scoped to the **audio stack** (DirectAudio + adaptive PulseAudio/ALSA) plus the driver-crash fix, Contents hub and the polish items above — nothing about controllers changed.

## ➕ Everything from 2.9.9, carried forward

All of 2.9.9 is included — including its controller/touch input fixes and deeper log capture, unchanged — on top of the 2.9.8 headphone-following audio and 2.9.7 controller reliability overhaul.
