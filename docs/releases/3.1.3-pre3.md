# What is in this release (all three flavours)

| File | What it is |
|---|---|
| `Bannerlator-3.1.3-pre3-standard.apk` | the normal app (`com.winlator.banner`) |
| `Bannerlator-3.1.3-pre3-pubg.apk` | the "pubg" package name flavour (`com.tencent.ig`) |

The Linux runtime itself (about 755 MB) is **not** in the APK — the app downloads it once, see Setup. Valve's ARM64 Proton (about 2 GB) is downloaded by the Steam client on your first sign-in. The patched gamescope and Valve's performance-overlay program are small and come inside the APK.

# Setup

1. Install the APK for your flavour over your current install (data is kept), or fresh.
2. Android **Settings → Developer options → Disable child process restrictions → on.** (If you do not see Developer options, tap *Build number* seven times in *About phone*.)
3. In the app: **Contents → Linux Runtime → Download.** One download, about 755 MB. When it finishes, a **Steam (Linux)** entry appears in your games list.
4. Launch **Steam (Linux)**. The first run shows a loading screen while the client downloads itself and updates (a few minutes; the clock on the screen tells you it is alive). Sign in with your Steam account (the QR code and the Steam mobile app work).
5. **Wait here — do not install a game yet.** The client fetches Valve's ARM64 Proton by itself, but it may not start on its own: watch for the **Proton Experimental (ARM64)** install box (about 2 GB) and, if the phone has an SD card, **choose internal storage or the card** and tap *Install*. If nothing appears, look in **Downloads** — it may be waiting on that choice.
6. **Let it restart itself.** When that download finishes the client restarts on its own — the loading screen comes back with "Steam is restarting once…" and goes away when Steam is back, still signed in. A game installed *before* that restart gets Steam's own tool chain (~1.7 GB it cannot use) and fails to launch with no error, so wait it out.
7. **After the restart:** install a game from your library and play it. That's it — nothing to pick. Your Games-tab games are already in the library under *Non-Steam*.

**Optional:**
- The ⚙️ next to the Steam (Linux) entry has its settings: resolution (720p by default — the client's interface is the most expensive thing a session draws), the **draw driver** (the Turnip that draws the client and its games) and the **display driver** (the one that puts frames on your screen), core lists for the client and for games, DirectAudio, frame generation, the HUD, **Your games in Steam** (on/off, shared saves, extra games folders) and the **Steam client update channel**.
- Other Turnips for drawing: **Contents → Drivers → import** one of the `-Linux.zip` builds from [Banners-Turnip](https://github.com/The412Banner/Banners-Turnip/releases) (there are plain, A8xx and 710/720 builds). The runtime ships one already; import only if you want to compare.
- **GE-Proton and proton-cachyos (ARM64 builds)** can be downloaded in **Contents → Linux Runtime** and chosen per game in the client's own *Compatibility* page. A game's per-game choice follows Steam's rules, not the app's.

### 🆕 New here? Installing for the first time

**Before you start — check two things:**

- **Your phone needs an Adreno GPU** (Snapdragon). Mali, Xclipse and PowerVR phones will get sound over a black screen. **Contents → Linux Runtime** warns you about this before the download.
- **Turn on one Android setting first:** go to **Settings → Developer options → Disable child process restrictions** and switch it **on**. Do not see Developer options? Go to **Settings → About phone** and tap **Build number** seven times, then it appears.
  Without this switch, Android randomly kills the Steam client and your session just dies for no visible reason. Some phones do not have the switch at all — on those, this build will not work yet.

**Then:**

1. **Download and install the APK.** There are three — just take **standard** unless you specifically use the pubg or ludashi build already.
2. **Open the app and go to Contents → Linux Runtime → Download.** This is about **755 MB**, once. It is not in the APK, so this step is required.
3. When it finishes, a **Steam (Linux)** entry appears in your games list. **Tap it.**
4. **First launch takes a few minutes.** You will see a loading screen — Steam is downloading and updating itself. There is a clock on screen so you know it is alive. It may restart itself once; that is normal.
5. **Sign in** with your Steam account. Password, or the QR code with the Steam mobile app — both work.
6. **⏳ Now wait. Do not install a game yet — this is the part people get wrong.**

   Steam fetches Valve's ARM64 Proton by itself. **It may not start downloading on its own** — watch for an install box for **Proton Experimental (ARM64)** (about 2 GB). If your phone has an SD card, Steam will ask **where to put it: internal storage or the SD card**. Pick one and tap **Install**. If nothing appears, check the **Downloads** page — it may be sitting there waiting on that choice.

   **When the download finishes, still do not touch anything.** The loading screen comes back saying **"Steam is restarting once…"** — **the client restarts itself automatically.** That restart is what makes every game you install run properly. Let it happen; Steam reopens on its own, still signed in.

   ⚠️ **Installing a game before that restart breaks it.** Steam grabs the wrong set of tools — about 1.7 GB you will never use — and the game just fails to launch with no error message. Wait for the restart. It is a minute or two.
7. **Once Steam has come back on its own — now install a game from your library and play it.** Nothing to configure, nothing to pick.

**That's it.** Your existing Wine containers and games are completely untouched by any of this. The games you added in the Games tab also show up in Steam's library under **Non-Steam**, and they use the same saves as in the app.

**Optional tweaks** — the ⚙️ next to the Steam (Linux) entry has resolution (720p by default, because Steam's own interface is expensive to draw), drivers, audio, frame generation, the HUD and **Your games in Steam**.

# What's New in pre-release 3

## 🎮 Your Games-tab games in the Steam client

The games you added in the app's **Games** tab now show in the Linux Steam client's library under **Non-Steam**, and you can start them from there — in Big Picture, from the desktop UI, or with the controller.

- ✅ **Written into Steam's library before the client starts,** with their artwork: the app's own cover when it has one, otherwise the game's Steam store art, fetched once and kept. Only entries the app made are touched; non-Steam games you added yourself stay as they are.
- ✅ **Shared saves.** The game's **Documents**, **AppData** and **Saved Games** folders in Steam's prefix are links to the same folders in the game's container, so progress carries over both ways. **Titanfall 2 loaded a save made in the app**, and DOOM I Enhanced wrote its save straight into the container's folder. A folder that already had something in it is renamed "(Steam's own, before sharing)", never deleted, and turning sharing off puts it back.
- 🧪 **Games folders:** add folders in the settings and each game folder inside them is listed too, started with the likeliest program in it (installers, updaters, settings tools and anti-cheat helpers are skipped). Built; not yet tried on a device.
- Left out on purpose: Steam's own games (the client already has them), and Epic and Amazon games, which need the app's own launch.
- ⚠️ **They run with Valve's Proton, not the app's own Wine, FEX settings and preset.** So a game that needs a particular preset in the app may not run here. **Proven:** DOOM I Enhanced and Titanfall 2. **Not yet:** Insane 2 crashes while starting up (a DLL it ships writes into the game's own program header), and DiRT Showdown and DiRT Rally 2.0 stop at their splash screen. All three still run in the app as before.
- ⚠️ **Saves kept in the registry are not shared** — only the folders above are. And **do not run the same game in the app and in Steam at the same time.**
- It is on by default: **Steam (Linux) settings → Your games in Steam**, with **Share saves with the app** under it.

## 🔊 DirectAudio really reaches games now, with PulseAudio behind it

Pre-releases 1 and 2 said games in the client use DirectAudio. **They did not.** The setting that picks Wine's audio driver was written under a registry key with its backslashes lost, and Wine read that as a different key, so every game quietly used PulseAudio instead — which is why game sound could crackle under load.

- ✅ **The key is written correctly now, and prefixes that already had the broken one are repaired on the game's next start.** On GE-Proton 11-7 the game log shows DirectAudio loaded and connected, and Titanfall 2 played with sound.
- ✅ **PulseAudio sits behind DirectAudio.** Wine keeps the first audio driver that loads, so DirectAudio wins wherever it can load, and PulseAudio takes over where it cannot, instead of the game having no sound device. That matters today because **Valve's Proton Experimental cannot load DirectAudio for 64-bit games yet** (our driver is not built for that kind of process). With DirectAudio alone, Titanfall 2 crashed before its menu there; now it runs with sound. Turning DirectAudio off also gives games PulseAudio, not silence.
- ⚠️ **A game's very first start uses PulseAudio.** Its prefix does not exist yet, so the setting can only be written for the next start.
- ⚠️ DirectAudio for 64-bit games on Proton Experimental is still to come; for DirectAudio today, pick **GE-Proton** for the game in the client's *Compatibility* page.

## 🔈 The Steam client's own sound through DirectAudio

When DirectAudio is chosen in the Steam (Linux) settings, the client's own sound — its menus, its startup chime, the Big Picture navigation sounds — now goes straight to DirectAudio as well, through a PulseAudio output made for it, instead of the generic Android sound path.

- ✅ On the AYANEO Pocket FIT the menu sound is clean, and the log shows the client's sound connected to DirectAudio.
- ⚠️ The SteamDeck app found this same path **choppy on an AYN Thor**. If the client's sound crackles on your device, please report it with the session folder.

## 🎛️ Steam Deck mode — fewer rough edges, still off by default

- ✅ **No more Steam Client update that cannot install.** Deck mode now runs the client on the **Steam Deck beta channel**, where the ARM64 client exists, and the SteamOS helper programs the client calls (system update, BIOS and dock firmware checks, branch selection) are answered by harmless stand-ins instead of failing. On device: no "Update Error", one client update when the channel switches, then clean starts.
- ✅ **The battery shows** in Steam's top bar and Quick Access Menu, read from Android every five seconds.
- ✅ **A Steam client update channel** setting: *Automatic* (the Steam Deck beta in Deck mode, the public beta otherwise), or pick one.
- 🧪 **The performance overlay** in the Quick Access Menu is drawn by Valve's own program, now shipped in the APK, and **NIS** is offered as a scaling filter in Deck mode. Both are built but **not yet tried on a device**.
- ⚠️ **Still breaks game controllers.** Steam's menus work, games get no pad. It stays off by default and only turns on through a warning.

## 🖥️ A patched gamescope

The session now runs a patched build of Valve's gamescope compositor (3.16.29), the same file the SteamDeck app uses, carried inside the APK. The runtime's own download is untouched. The patches, mostly from the Armada project:

- **Night mode and the colour-temperature slider** work with the ARM64 client, which sends those values in a different shape; before, the sliders did nothing.
- **The cursor follows the controller** when a pad drives the pointer (it sat frozen).
- **Realtime-priority GPU queues** when asked, without the system permission proot can never have.
- A focus fallback for games whose app ID gamescope cannot read, and P3 red counted as wide gamut.
- ✅ Proven running on device: the session log names `gamescope version 3.16.29+` at `/usr/local/bin/gamescope`. The individual fixes above have not each been checked on a device yet.

## 🧹 Starting after a killed session

- 🧪 If the last session was killed rather than closed, the client could come up believing it had crashed, or with its interface's lock files still held. Before the client starts, and only when no client is running, the session now clears Steam's crash marker, its PID file and those interface locks, and says so in the session log. Built; not yet seen on a device.

## 🚀 The Steam client's interface is back on the GPU

The Steam client draws its interface with Chromium, and Chromium names the video card through a small library called libpci. libpci decides how to read the PCI bus by checking whether it can see the `/proc/bus/pci` folder — which an Android app can — and then opens the device list inside it, which Android does not allow. When that fails, libpci does not return an error: it ends the whole process. So Chromium's GPU process died on its way up, every time, and after a few tries Chromium gave up on the GPU and drew the rest of the session on the CPU.

- ✅ An empty device list now answers that question truthfully from inside the runtime — nothing the app can see is on a PCI bus — and the GPU process stays up.
- ✅ **Measured A/B** (OnePlus 15, same install, same d-pad scroll through the Big Picture library): **~44 fps before, ~85 after**, against a gamescope asked for 90; GPU-process crashes **12 → 0**. On an AYANEO Pocket FIT the interface reads **117–138 fps**.
- ✅ It takes effect at session start, so an installed runtime is fixed with no re-download. It only steps in when the real file is unreadable, so it can never hide real hardware.
- Found and fixed by **maxjivi05** in WinNative (`deff1ac6`); ported here with thanks.

## ⚠️ Warnings before the download

Two failures used to end a session with nothing on screen and nothing in any log. **Contents → Linux Runtime** now checks for both before the 755 MB download:

- ✅ **Android's child-process limit.** A Linux session is dozens of processes, and Android 12 and later kill an app's extra child processes. The card says when that limit is still on; on Android 14 and later it has a button that opens Developer options, and on older versions it gives the one-line adb command, because there is no switch in the settings there. The app cannot change this setting itself — Android only lets the system do that. (Detection follows maxjivi05's in WinNative, `e86cc2fc`.)
- ✅ **A GPU that is not an Adreno.** The runtime draws with Turnip, an Adreno driver. On Mali, Xclipse and PowerVR a session comes up as sound over a black screen, so the card names your GPU and says so first.

## 🖥️ Scaling mode and scaling filter

Two new rows in the **Steam (Linux)** settings, handed straight to gamescope:

- ✅ **Scaling mode:** Auto, Integer, Fit, Fill or Stretch.
- ✅ **Scaling filter:** Linear, Nearest, Pixel, **FSR**, **NIS** or **SGSR**. SGSR is Qualcomm's own upscaler, made for Adreno.
- They only change anything when a game renders below the session's resolution. Only values this gamescope accepts are ever passed, because an unknown one would stop the session from starting.
- For a frame cap, use the in-game drawer's FPS limit.

## 🎮 Controllers

- ✅ **Only the controllers you actually have are listed to Steam.** Four were always listed, with one real pad behind them and three that never moved. Now it is one node per connected pad, plus one for the on-screen controls; a pad plugged in mid-session still appears.

## 🐧 proot

- ✅ **A crash fix.** If the runtime's own proot is missing — a download cut short, or an older runtime — the app falls back to the proot built into the APK. It was handing that copy an option it does not have, which is fatal before anything starts: the session died instantly, with no window and nothing in the log. The option now only goes to the binary that takes it. (The same fault was found independently in WinNative, `b6b2fce8`.)
- ✅ **Faster memory handling.** proot copies data between itself and the programs it runs — every file path, for a start. It did that eight bytes at a time; it now moves each piece in one call, and it no longer trips over the tagged pointers Android puts on memory. (From maxjivi05's WinNative, `290c5314` and `0c71304a`.) This only affects the APK's own proot, which the runtime's usually replaces.

## 🎛️ Steam Deck mode — experimental, and off by default

A **Steam Deck mode** switch in the Steam (Linux) settings runs the client the way it runs on a Steam Deck. That brings Steam's **Quick Access Menu**, with its performance page — the frame limiter and scaling controls.

- ⚠️ **On device, it breaks game controllers.** Steam takes the pad over through Steam Input, the way a real Deck always does, and hands the game a virtual controller that never arrives here. Steam's menus keep working; the game gets nothing. Turning Deck mode off brings the controls back.
- ⚠️ It shows a **Steam Client update** under **System → Software Updates** that cannot install. **Do not press Apply.** The ARM64 client is only published on the beta channel, and Deck mode switches the client to the Deck's stable channel, where there is no ARM64 build.
- ⚠️ The Quick Access Menu's **performance overlay** cannot be turned on: on a Deck it is drawn by a program the runtime does not ship.
- So it only turns on through a warning that lists all of this, with a red line under the switch while it is on.
- ✅ Deck mode no longer throws the client into a restart loop. It used to also claim to be SteamOS, which changed the client's update channel on disk and left it restarting to install an update that could never land. That flag is gone, the update channel is put back before every start, and any client update that keeps asking for a restart is stopped after three tries.

## 🧪 Three experimental rendering switches

The **Performance (experimental)** part of the Steam (Linux) settings also has three switches that make the chain drawing Steam's interface cheaper: **Threaded GL** (`mesa_glthread`), **Lazy descriptors** (`ZINK_DESCRIPTORS=lazy`) and **Skip GL error checks** (`MESA_NO_ERROR`). All three are on by default. None is measured on this device yet — if you try them, change one at a time. Whatever is in effect is written into the session's `device.txt`.

## 📝 Logs

- ✅ Session logs now keep the **first 600 lines** of a big log as well as the last 3000. The GPU-process fault above only ever wrote its reason while starting up, and a log trimmed to its end could not show it.

## 🐧 The Linux Steam client

Valve ships a native ARM64 Linux Steam client. Bannerlator now runs it, inside a small Arch Linux ARM root filesystem, under Valve's **gamescope** compositor, on top of the same embedded Wayland compositor 3.1.2 introduced. What that means in practice:

- ✅ **It is the real client:** sign-in (password, QR, Steam Guard), the library, the store, downloads with Steam's own resume and verification, cloud saves, the overlay, friends and chat, Big Picture and the desktop UI, controller configuration, the shader pre-cache.
- ✅ **Games run through Valve's ARM64 Proton** (the depot the client downloads, wrapped as a *Bannerlator Proton (ARM64)* compatibility tool that runs it without the Linux runtime container Android cannot provide). Wine, DXVK, VKD3D and FEX are Valve's own, matched to each other. Only the Turnip driver is ours.
- ✅ **No container.** The client has its own settings entry; no Wine prefix is created or touched. Your existing containers, games and shortcuts behave exactly as before.
- ✅ **Your games in one place:** the app's own game folders (phone and card) are the client's library folders, so a game the app installed shows up installed in the client, a game the client installs lands where the app would have put it, and nothing is ever copied. Uninstalling in the client releases it in the app.
- ✅ **The account's owned games and the anti-cheat runtimes** (BattlEye, EAC) are mapped to the ARM64 tool before the client can reach for anything x86.
- ⚠️ **First-run window:** a game installed in the couple of minutes while Valve's ARM64 Proton is still downloading gets Steam's own tool chain assigned for that session (about 1.7 GB of downloads it then cannot use). The automatic restart when the layer lands fixes the assignment; the extra download stays. Launching a game in that window fails quietly. After the restart there is no window.

## 🧭 A first run that takes care of itself

Tested from a clean install, start to finish, and each of these was a real problem on the way:
- ✅ **Loading screen** until the client draws its first frame: the runtime's milestone, the client's own download percentage, a clock, and a rotating hint. It comes back for the client's self-update restart and for the compatibility-layer restart, and leaves on the first frame — the picture arrives with Steam's start-up chime, not five seconds after it.
- ✅ **The compatibility layer is fetched after you sign in,** not before (a signed-out client silently drops the request). When it lands, the client restarts itself once so everything installed before or after that point runs through it.
- ✅ **A fresh install starts on Turnip.** The old default was the proprietary driver, which cannot share frames with the compositor: sound over a black screen for every new user.
- ✅ **Opening the Steam (Linux) settings no longer crashes** on a fresh install (its entry has no Wine, Box64 or FEX to speak of, and the editor assumed it did).
- ✅ A session that dies before the client ever draws shows its exit status and log folder for a moment instead of a flash of black.

## 🔊 DirectAudio, and a microphone

- ✅ Games in the client use **DirectAudio** (the same low-latency Android path Wine games use), chosen in the entry's settings.
- ✅ The Steam client gets an input device — **DirectAudioMic** — with a working voice slider, proven in Steam's own voice tester. Five separate faults sat behind "no input device"; they are all gone.

# What it can and cannot do right now

**Can:**
- **Steam:** sign in, browse, install, update, verify, cloud-sync and play games from your library, with the overlay, Big Picture or the desktop UI, on a controller or on the touch screen.
- **Your own games:** the Games tab's games in Steam's library under *Non-Steam*, with artwork and shared saves.
- **Games:** the Source titles, GTA V (Legacy), NFS Most Wanted and Payback, FlatOut 1 and 2, Brawlhalla, DiRT Showdown, Titanfall 2, DOOM I Enhanced — playing, on one device.
- **Sound:** DirectAudio for games (PulseAudio where it cannot load), DirectAudio for the client's own sound, a microphone for the client.
- **Drivers:** pick the drawing Turnip per entry; import Linux builds from Banners-Turnip.
- **Scaling:** gamescope's scaling mode and filter per entry, FSR, NIS and SGSR included.
- **Also:** frame generation, screen effects and the HUD on the client's sessions, the battery in Steam's UI, session log bundles you can post.

**Cannot yet, or not proven:**
- **Mali, Xclipse and PowerVR:** nothing. The runtime's driver is Turnip. The app says so before the download.
- **Phones without the "Disable child process restrictions" switch:** the session is killed at random. The app detects the limit and warns before the download; a one-tap fix with root or Shizuku is still to come.
- **Steam Deck mode:** breaks game controllers — Steam's menus work, games get no pad. Off by default, behind a warning. Its performance overlay and NIS are untested.
- **Steam Input for games** (per-game layouts, remapping, gyro): the virtual controller Steam Input hands a game does not reach it yet. Games read your pad directly instead, which works.
- **Games-tab games that need the app's own Wine or FEX preset** may not run from Steam: Insane 2 crashes, DiRT Showdown and DiRT Rally 2.0 hang at the splash. Saves kept in the registry are not shared.
- **DirectAudio for 64-bit games on Valve's Proton Experimental:** not yet — they get PulseAudio. GE-Proton gets DirectAudio.
- **FlatOut** shrinks to the top-left corner after **Guide → Resume game**. FlatOut 2 does not.
- **GTA V Enhanced** does not run (a null call in x86 code under FEX, ~2 minutes in). **Serious Sam Shatterverse** is killed by Android for memory during its shader burst. **NFS Hot Pursuit Remastered** faults inside FEX.
- **TF2 "insecure"** — open, see above.
- **Voice chat with people** — untested. **Remote Play, streaming, family sharing** — untested.
- **Join-a-friend / invites** — built, not proven.
- **Steam Controller** — untested.
- **The client's desktop session** (the *Linux Desktop* entry) has had far less testing than Big Picture.
- Leaving the app pauses the session; come back and it resumes. That is by design.

2. **The process-limit switch:** the app detects it and warns. Still to do: flip it with root or Shizuku where the phone allows.
3. **Steam Input's virtual controller:** make it reach games, which is what Steam Deck mode needs and what per-game controller layouts need.
4. **FlatOut's shrink after Resume:** a one-line gamescope option is the likely fix; it needs a check on a device.
5. **Games-tab games that do not run from Steam:** Insane 2, DiRT Showdown, DiRT Rally 2.0.
6. **The first-run window:** keep Steam's own tool chain from being pulled in when a game is installed before the layer lands.
7. **TF2 secure status:** connect to a real secure server with `-condebug` and let the game say why.
8. **A tester matrix beyond one device:** Adreno 830/840 phones, Thor (especially for the client's DirectAudio sound), and the phones that reported black screens.
9. **Performance:** measure the three experimental rendering switches now that the interface is on the GPU, and trim what the client costs while a game runs.
